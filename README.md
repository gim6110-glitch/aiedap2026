### 최종 PDF의 정확한 원본 화면을 보는 방법

기존 GitHub 저장소는 오래된 슬라이드 이미지를 HTML 안에 직접 포함하던 방식이어서, **83쪽으로 재배치한 화면 중 일부는 임시 미리보기/기존 이미지**입니다.

정확한 최종 PDF를 모두에게 보여주려면 GitHub 저장소 **최상위(root)** 에 파일명 **`course-final.pdf`** 로 최종 83쪽 PDF를 업로드하세요.

- GitHub → `Add file` → `Upload files` → `course-final.pdf` 파일 추가 → `Commit changes`
- Netlify가 자동 배포되면 모든 참여자에게 동일한 83쪽 원본 PDF가 표시됩니다.
- GitHub 업로드 전에도 웹페이지 상단 **「최종 PDF 연결」** 버튼에서 본인 기기의 최신 PDF를 선택하면 해당 브라우저에 저장되어 정확한 원본 화면을 볼 수 있습니다. 이 경우 **다른 기기에는 자동 공유되지 않습니다.**
- PDF 파일을 업로드하지 않아도 활동지 작성·저장·내보내기는 가능합니다.

### 데이터 안전

- 기존 답변 필드 ID를 그대로 유지합니다. 예전 브라우저 저장 데이터는 **이전 슬라이드 번호 → 83쪽 번호**로 자동 이동 처리합니다.
- 이름·학교를 동일하게 입력하면 이전 작성 내용을 이어서 사용합니다.
- JSON 백업/복원, XLSX/DOCX/HWPX 내보내기 기능을 유지합니다.
- 성취기준 원문은 바꾸지 않고, **AI와 연결한 학생 수행 및 증거** 항목을 추가했습니다.
- 정보과 4개 유형을 타 교과에 강제하지 않고 **「기타(교과 중심)」** 선택과 교과 핵심 수행 기록을 지원합니다.
- 동료 의견은 강점 중심으로 입력하며, 타 교과 교사의 수업을 단순히 AI 사용 여부로 평가하지 않습니다.

### 주의

- 이 웹앱은 서버 로그인·동기화가 아닌 **브라우저 로컬 저장**입니다. 다른 기기에서는 JSON 백업을 사용하세요.
- 첨부하는 실제 학생 자료에 개인정보를 포함하지 마세요.
- XLSX 내보내기는 입력형 활동지이며 공식 활동지 서식과 완전히 같지는 않을 수 있습니다.
- HWPX 파일은 한컴오피스 버전에 따라 편집 호환성을 확인해야 합니다.
